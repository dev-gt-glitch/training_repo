# Waterfall and Agile SDLC Comparison

## Waterfall

Waterfall organizes work into sequential phases, such as requirements, design, implementation, testing, and release. A phase is generally completed before the next begins. This can fit work with stable, well-understood requirements, formal approval gates, and a need for predictable handoffs. For example, a small internal reporting tool with a fixed specification and regulated sign-off may benefit from documented phase gates.

The main trade-off is that feedback arrives later. If users discover a requirement change during testing, earlier decisions and documents may need substantial rework.

## Agile

Agile delivers work in short cycles, using feedback to adjust the backlog and product. A team can plan a small set of stories, build and review them, then use what it learned to plan the next cycle. Scrum is one framework for this approach, with defined roles, events, and artifacts; Kanban focuses on visualizing and managing ongoing flow.

For the task tracker in this training plan, an iterative approach fits well: first make a static task list, then add browser behavior, an API, persistence, and a UI. Each increment can be reviewed and improved before the next layer is added. The trade-off is that scope and priorities need active management, and frequent collaboration is important.

## Summary

Waterfall can work when requirements and approval gates are stable. Agile is useful when a team can deliver in increments and learn from feedback. The choice depends on the work, its constraints, and how much the requirements are expected to change.
